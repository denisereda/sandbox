# Сквозное практическое задание

## Начальные требования

1. УЗ GitLab.
2. УЗ Yandex ID.
3. Регистрация и первый вход YC, с настройкой платежного средства.
4. Установка Docker (deocker desktop / docker engine).
5. Установка Git.
6. Установка VSCode и расширений (Docker, Git Graph, YAML, markdownlint, Container Tools, Dev Containers).  

## Этап 0

На предварительном этапе необходимо настроить инструменты для работы:

1. Проверить наличие и работоспособность Docker.
2. Поставить наличие VSCode.
3. Поставить Git + git bash (можно добавить средства GUI).
4. Проверить наличие УЗ на gitlab.com.
5. Создать репозиторий sandbox.
6. Создать / перейти в директорию для хранения проектов (source, projects) (ремарка по правилам именований репо в kebab-case).
7. Создать ключ, подложить ключ в GL.
8. Клонировать репозиторий на локальную машину.  
9. Расположить в него необходимые файлы DevContainers (используя базовые команды терминала).
10. Поставить DevContainers, запустить DevContainers, проверить работу утилит, остановить DevContainers.

## Этап 1: Docker, Yandex Cloud (локальная сборка, развертывание вручную на VM)

На первом этапе необходимо:

1. Получить исходный код сервиса от преподавателя.
2. Собрать приложение в виде raw-артефакта на локальной машине (варианты сборки на выбор (в порядке предпочтения): сборка в docker-контейнере в интерактивном режиме, запуск команды сборки (хорошо, но чуть сложнее для понимания и обучения, лучше сделать после прохождения первого способа), сборка в образе с дальнейшим вытаскиванием наружу через создание контейнера и вытаскивание артефакта из volume (можно но сложно и не является целевым вариантом для сборки "на коленке", однако заложит дальнейший фундамент для сборки под развертывание в контейнере)).
3. Запушить в артефакторий, предложенный преподавателем. Настроить версионирование сборки, самостоятельно предложить варианты. <-- НАЛИЧИЕ АРТЕФАКТОРИЯ с доступом по имени пользователя и паролю.
4. Поднять виртуальную машину в облаке YC, получить к ней доступ через консоль.
5. Научиться передавать артефакты на удаленную машину с помощью подключения через SSH (утилита `scp`).
6. Получить и изучить инструкцию по настройке и запуску сервисов с помощью подсистемы `systemd`.
7. Научиться стягивать свежие артефакты на удаленную машину из артефактория и запустить полноценно приложение в подсистеме `systemd`.

## Локальная сборка и запуск решения в docker

Для создания Dockerfile используйте наработки с прошлого урока.

Ваши файлы должны быть созданы с использование подхода multistage: стадия `builder` - для сборки, стадия `runtime` - для запуска приложения.

Для запуска приложения backend используйте тот же образ, что и для сборки.

Для запуска приложения frontend используйте образ node с установленным web-сервером `http-server`.

Запускайте процесс через отдельные sh-скрипты (по одному файлу на каждый из компонентов системы). Назовите их: `biild-docker.sh`. Скрипты сборки с предыдущего урока, которые производят сборку и отправку артефактов на nexus переименуйте в `build-raw.sh`.

## Запуск решения в docker compose (без сборки)

При создании docker compose:

1. Создайте выделенную сеть для вашего приложения.
2. Не используйте стадию сборки (ваш docker-compose.yaml будте использоваться для развертывания приложения, поэтому стадия сборки не будет уместна).
3. Используйте тег `latest` для первичной проверки.
4. Подключите файл с переменными окружения к конфигурации и пробросьте все необходимые параметры и секреты через переменные окружения (`env_file`).

При тестировании вы должны получить возможность использования браузера на локальном хосте для полноценного запуска приложения и проверки его на работоспособность.
